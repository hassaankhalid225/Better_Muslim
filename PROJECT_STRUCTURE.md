## 🏗️ Architecture Principles

### Clean Architecture Layers:

1. **Presentation Layer** (UI + BLoC)
   - Pages: UI screens
   - Widgets: Reusable UI components
   - BLoC: Business logic and state management

2. **Domain Layer** (Business Logic)
   - Entities: Core business objects
   - Repositories: Abstract interfaces
   - Use Cases: Application-specific business rules

3. **Data Layer** (Data Management)
   - Models: Data transfer objects with JSON serialization
   - Data Sources: Local (SQLite) and Remote (API) data access
   - Repository Implementations: Concrete implementations of domain repositories

### SOLID Principles Applied:

- **S**ingle Responsibility: Each class has one reason to change
- **O**pen/Closed: Open for extension, closed for modification
- **L**iskov Substitution: Derived classes are substitutable for base classes
- **I**nterface Segregation: Many specific interfaces over one general interface
- **D**ependency Inversion: Depend on abstractions, not concretions

### Key Design Patterns:

- **Repository Pattern**: Abstraction over data sources
- **Dependency Injection**: GetIt with Injectable for loose coupling
- **BLoC Pattern**: Separation of business logic from UI
- **Factory Pattern**: Object creation
- **Singleton Pattern**: Single instance services (Database, API client)
